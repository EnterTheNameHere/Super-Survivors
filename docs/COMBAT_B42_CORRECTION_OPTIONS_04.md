# Combat04: first native attack transition and correction options

2026-11-17. SSR-COMBAT-04. Source research and future experiment design only. No fixture, combat fix, flag reset, damage injection, Java change or runtime experiment was performed.

## Decision

There is no verified end-to-end Lua-native combat correction for a standalone nonlocal SSR IsoPlayer in the inspected build. pressedAttack is a real, Lua-exposed initiation entry point, and its body does not categorically exclude a single-player NPC. It is not sufficient to establish a swing or native damage. Two independent boundaries remain:

1. NPC initiation is overwritten from AIComponent's humanControlVars before the normal action-context animation transition in the scheduled update/post-update path. SSR does not supply these controls. This is a concrete mechanism for losing a request while leaving attackStarted latched, not yet the observed first cause for the traced actors.
2. The ordinary SwipeStatePlayer AttackCollisionCheck listener requires isLocalPlayer. A standalone SSR NPC fails that gate even if animation initiation is repaired. No supported alternative Lua collision entry point was found in the audited installed API/exposure paths.

The smallest next assignment should be a bounded observation of an existing, provenance-known fresh NPC before its first natural request, including request/StopWalk boundaries and native update samples. Do not repeat already-busy traces, patch flags or claim that an initiation-only change solves combat. A native damage path must be established independently before a complete correction can be accepted. Java modification remains excluded.

NetworkComponent.isLocal returns true in SP regardless of local-player slot membership; IsoGameCharacter.isLocal delegates there. IsoPlayer.isLocalPlayer instead compares exact actor identity with players[0..numPlayers-1] and is false on server. These are different predicates. NPC setParams uses the isLocal branch in SP; replacing an isLocalPlayer gate with reasoning about isLocal is invalid. No player-index, camera or singleton workaround is proposed.

## Flag writer inventory and initial state

The current-JAR reference scan and source follow-up found these ordinary direct sites. This is not a claim that arbitrary Lua/mod animation-variable writes are impossible.

| Writer | Flags / applicability |
| --- | --- |
| IsoPlayer fields/constructors | attackStarted and initiateAttack have Java false defaults; no explicit true constructor initialization found. IsoPlayer registers initiateAttack as a getter/setter-backed animation variable. A string-named variable write can therefore reach its setter without a direct setInitiateAttack call site. |
| CombatManager.pressedAttack | Sets both true; unauthorized shove/grapple clears both. Primary ordinary first-request candidate. |
| AIComponent.postUpdatePlayer | Sets initiation from control vars every completed NPC update; never sets started. Control vars are freshly allocated public booleans/floats with false/zero defaults. update() is empty in this build. |

| IsoPlayer.clearHandToHandAttack | Clears initiation and started/type; called on legitimate hand-to-hand failure paths. Not a recovery command to invoke artificially. |

| IsoMovingObject.separate | Spear-charge contact can set started=true plus CHARGE, behind movement/sprinting/spear/facing predicates. Alternative native setter, not the ordinary one-handed attack case; don't ignore it or generalize it to Roderick without evidence. |

| network.fields.hit.Player.attack / PlayerEmptyShotPacket.processClient | Client replay clears started or sets both for empty shots. Network behavior; not an SP standalone-NPC control path. |
| SSR StopWalk, SuperSurvivor.lua:3268 | Clears initiation, attack-target square, aiming, trigger and movement/actions/path, but not started. Called before native pressedAttack and also by later path/task/completion routes. |

Fresh creation in SuperSurvivor.lua:555 constructs IsoPlayer, then blocks movement and sets NPC. Native setNpc(true) installs a new AIComponent only on a false->true change; repeating true preserves the existing component. Toggling NPC off/on destroys/recreates controls and is not a harmless flag fix.

Native-loaded SSR creation (loadPlayer at :487) also constructs a new IsoPlayer, sets NPC, invokes native load, validates snapshot identity/generation, restores saved position and sets NPC/block movement again. Inspected IsoPlayer/IsoGameCharacter native save/load methods do not explicitly serialize/restore these two attack flags or AI human controls. This supports sampling new and newly loaded actors before their first update; it does not prove both were false after all load callbacks/mods. Loading into an already existing stuck actor is a different case and is not guaranteed to clear its existing fields. No migration or persistence change is warranted from this result.

Working-source request/update/StopWalk chain was compared with current source HEAD: the preserved user changes are local/comment renames in the audited areas, not a different attack API implementation. Existing busy observations cannot be attributed to native loading, StopWalk or AIComponent alone without the initial timeline.

## Java APIs versus Lua access

The installed LuaManager.Exposer explicitly registers IsoPlayer, IsoGameCharacter and SwipeStatePlayer. LuaJavaClassExposer exposes eligible public methods, excludes HiddenFromLua/private methods and emits static class tables with a class token for registered classes. Recursion still consults Exposer.shouldExpose, which checks its whitelist. A Java public signature in Javadoc is not sufficient evidence of a usable Lua call.

| Candidate | Installed contract / Lua accessibility | Stages, risks and acceptance |
| --- | --- | --- |
| actor:pressedAttack() | Public ()V, on exposed IsoPlayer, no hidden annotation found. Verified source-level Lua binding; not called by this audit. | Initiation only. Preserve native guards. Requires pre-false natural request -> immediate flags -> native state/animation and later cleanup evidence. Does not solve local collision gate. |
| AttemptAttack() / DoAttack(float[,String]) | Public on exposed IsoPlayer. AttemptAttack calls DoAttack; DoAttack checks hand-to-hand authorization, calls pressedAttack and returns false in this implementation. | Not an alternative NPC pipeline. Its Boolean is not an acceptance result. Changing method name is not a correction. |
| setIsAiming(bool) / setInitiateAttack(bool) | Public on exposed actor. Ordinary aim setter writes isAiming, but NPC isAiming reads AI controls (except special throwing override). Initiation setter is subsequently overwritten by AI post-update. | Field-level access exists, but polling/reassertion would race native lifecycle and still not produce native collision. No supported end-to-end alternative was established by the inspected classes, Lua globals, installed Lua or public docs. This is a scoped negative finding, not a proof that every future engine/mod API is incapable of NPC combat. With Java changes and direct synthetic damage excluded, a full damage fix remains unproven rather than something to hide behind an animation-only workaround.

## Smallest next experiment: design only

Proposed next bounded assignment: **observe the earliest natural handoff of one existing fresh NPC**, reusing contextual Diagnostics and existing exact-once observer design. No feature is implemented by this report.

1. Preconditions: explicit user start; debug enabled; one exact loaded/live nonlocal SSR NPC bound by stable ID, wrapper, actor and world; attackStarted=false, initiateAttack=false, no Swipe/hostile animation. Require known new-actor/never-attacked provenance to call it a first attack. False flags alone do not prove that history; otherwise label it only earliest observed request. Reject preexisting busy actors instead of logging another busy trace. No resets, repositioning, weapons, targets, AI changes or spawned entities.
2. Capture initial identity/origin (fresh or native-loaded, if supported by existing metadata), current task/target, native range/readiness, held weapon type, NPC/local/local-player predicates, running/block movement, native state/action-context names and relevant read-only variables (Weapon, initiateAttack, AttackAnim, bDoShove, rangedWeapon). Use only verified read-only APIs; unavailable fields must stay unavailable. Never call WeaponReady/DoVision/task update or getters known to consume attack vars just to observe them.
3. Observe the selected wrapper's natural requestCombatAttack before/after, exact-once and original return/error behavior preserved. A second instance-local observer on its natural StopWalk records before/after without changing the call; record whether it happened inside the request or later. Do not intercept native setters, replace class methods, change event order or call an attack. Preserve Kahlua's direct-original-call/error behavior from Combat03; no pcall around production invocation.
4. Add identity-filtered OnPlayerUpdate samples (early native boundary), OnTick samples and OnWeaponSwing/OnWeaponSwingHitPoint counters. Record callback label plus native frame and monotonic timestamp. Event subscription order is not a complete ordering proof; early/late samples bracket effects, not individual Java setters. Animation post-update may be threaded; treat OnTick/event chronology conservatively rather than claiming every sampler is after animation completion.
5. Bounds: one actor, at most 10 real seconds or 600 ticks, 120 lines, eight natural request entries; stop sooner after the first accepted request plus three subsequent simulation ticks, or after one first swing/hitpoint plus a short cleanup sample. No-request deadline -> inconclusive; preexisting true -> unavailable; capped interval -> censored. Separate coarse heartbeat from change records so early repeated states cannot consume the log before the transition. No auto-rearm or startup monitor.
6. Cleanup: close/cancel, target replacement, death/unload, world/menu transition, debug disabled, observer failure and reload; remove owned callbacks and restore only the observer's owned raw wrapper slots, leaving outside replacements intact. If engine stops dispatching, cleanup on first resumed callback. Prove human UI/player slots/singleton, actor flags, AI queue and native request count are unchanged by observation.
7. Interpretation: before false -> immediate started/initiate true -> early native true -> later initiate false/started true with no swing is evidence of the loss interval. A logged later StopWalk could explain a Lua cancellation; absence narrows but does not prove AIComponent is the sole writer. OnWeaponSwing demonstrates entry; AttackAnim demonstrates clip state; HitPoint demonstrates native collision entry; none alone proves damage. An observed swing without HitPoint is consistent with the known nonlocal gate but still needs identity/event-availability checks.

If no existing actor has suitable provenance, return inconclusive; do not silently spawn one. A later **separately consented disposable-world fixture** could sample immediately after construction, after native load (separate run), after SSR setup and before registration/first update, then allow normal AI to engage. It must carry existing world-modification consent, independent human guards and owned-actor cleanup. No such fixture or forced attack is authorized now.

## Acceptance before any correction

- First establish a reproducible natural false->true request and its next native update/state outcome; preserve the old evidence instead of overwriting it.
- Any proposed control adapter must have a verified normal Lua-accessible contract and explicit ownership/release. It must not reassert/reset latch flags each frame, toggle NPC state, drive native updates twice or alter human slots/camera/singleton.
- Animation acceptance: one native request -> correctly entered/exited swing with natural flag cleanup, repeatable second natural attack, native ammo/condition/interrupt behavior, no human action contamination. This proves initiation only.
- Damage acceptance is separate: supported nonlocal native collision route identified, exactly one collision per swing, valid hit versus miss/obstruction/out-of-range, actual attributable victim health/death change, native ammo/condition/stamina/XP handling, no double damage, no direct Hit and no Java patch. Use actor/victim identity and distinguish invincibility or other actors' damage. If that route remains inaccessible, report the limitation and seek a scope decision rather than ship a cosmetic swing as combat.
- Keep Test04 R1 baseline/restart proof, Test03 deferred observer and inventory roadmap unchanged. No production merge is implied by accepting this research.
